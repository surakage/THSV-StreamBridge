# THSV StreamBridge 4.0.8

## Final setup and live-reliability hardening

- Verified bundled extensions update transactionally with the Bridge while retaining enablement, approved action IDs, settings, and state; uninstalled extensions stay opt-in.
- Pre-stream checks refresh running broadcast-app scene evidence before judging it stale and explain the result as core readiness, ready to stream, or optional attention with a direct fix.
- Streamer.bot-dependent startup jobs share a connection gate, while setup presets and evidence-based progress reduce manual first-run bookkeeping.
- Exact Streamer.bot registries can be extended through a bounded GitHub/Sigstore-attested compatibility-data release without weakening fail-closed trigger repair.
- Scene selectors are searchable and grouped by current, previously used, likely, and other scenes; decorative separator rows are hidden by default.
- Repeated logs are summarized, rotated logs are compressed, and launcher logs normalize legacy oversized rotations.
- New move-computer launchers create and restore an encrypted settings/state/assets bundle that deliberately excludes credentials and requires re-entry on the destination computer.
- Verified Streamer.bot compatibility data is cached for 30 days with Sigstore re-verification, expiry enforcement, and release rollback rejection so offline startup stays trusted.
- Aggregate logs are pruned to a fixed storage ceiling at startup and hourly without deleting active service evidence.
- Sanitized command-publication attempt history survives Bridge restarts, and every new recovery or move bundle must authenticate before it is reported as ready.

Version 4.0.8 closes the Streamer.bot overwrite-import trigger gap found during the 4.0.7 local migration. It keeps the recovery narrow, creator-approved, rollback-protected, and fully visible in the wizard.

## Seamless import recovery

- The universal import keeps Streamer.bot 1.0.7 as its stable floor; the trigger reconciler selects an exact tested 1.0.7, 1.1.0-alpha.3, or 1.1.0-alpha.4 registry.
- After importing, **I finished importing — verify now** reads the saved action database without changing it.
- The wizard distinguishes a repairable missing trigger from a missing action that requires regenerating and importing the current package.
- A repair preview separates created triggers, re-enabled triggers, disabled duplicates, and re-enabled managed actions.
- The guided recovery creates a verified backup, applies only supported changes while Streamer.bot is closed, starts the selected executable safely, and runs the suppressed integration rehearsal.
- Pre-stream readiness now trusts the installed trigger evidence instead of a manual confirmation checkbox.

## Transaction and compatibility safety

- Trigger creation is allowed only when the selected executable reports Streamer.bot 1.0.7 or the separately captured 1.1.0-alpha.3/alpha.4 builds and the managed action schema is recognized.
- Twitch, YouTube, and Kick trigger records use type-specific defaults verified against both exact accepted schemas.
- Repairs preserve managed action bodies and stable action identities.
- Writes retry bounded transient Windows file locks, reread the persisted result, and automatically restore the original file if validation fails.
- New rollback backups include SHA-256 integrity metadata. Existing backups remain visible as legacy unverified backups; a failed verified hash cannot be restored.
- Trigger rollback storage retains the newest 20 backups and removes each expired backup together with its integrity sidecar.
- Package installation uses Streamer.bot 1.0.7 as its minimum baseline. Trigger repair is deliberately stricter: only 1.0.7, 1.1.0-alpha.3, and 1.1.0-alpha.4 are write-enabled, while every later alpha or schema remains read-only.

## Release verification

- The Windows candidate gate recreates the complete overwrite-import incident: 29 triggers missing, 29 restored as Twitch 10/10, YouTube 10/10, and Kick 9/9, action bodies unchanged, readiness retained after the restart boundary, and rollback verified.
- The reusable installed-settings rehearsal upgrades a private temporary copy of a creator installation and compares content fingerprints for configuration, secrets, private integration state, and add-on state without starting or changing the active installation.
- Public previous releases can be resolved and downloaded through GitHub's public APIs when the local CLI session is unavailable; the same checksum and GitHub attestation are still required before lifecycle testing.
- Type checking, lint, configuration validation, 1,214 passing unit and integration tests with 3 intentional skips, and all 62 browser tests gate this candidate.

## Install or update
