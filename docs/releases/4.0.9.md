# THSV StreamBridge 4.0.9

## Setup and operational resilience

- Starts the next application release line at 4.0.9 so the published 4.0.8 tag and assets remain immutable.
- Warns in the wizard when verified Streamer.bot compatibility data is within seven days of its 30-day offline expiry, including the exact days remaining.
- Exercises the protected-release fallback with intentionally failing GitHub CLI credentials and verifies public release discovery plus public attestation retrieval/offline verification.
- Replaces the compatibility cache and command-publication history through a flushed, recoverable Windows transaction that restores the previous valid file after interruption.
- Tracks active service output and archived logs under independent storage ceilings; archive cleanup can no longer be delayed by active output, and active-log pressure stays visible without deleting current diagnostic evidence.
- Displays the two storage lanes directly in the pre-stream confidence card.
- Runs a daily unauthenticated public-release canary that downloads the latest stable archive and verifies both its checksum and GitHub SLSA provenance before release day.
- Keeps a dedicated, checksum-verified Node 22.23.1 runtime cache for repeatable Windows packaging when nodejs.org is temporarily unavailable.
- Adds a real Windows ACL acceptance lane and gates release publication on protected secrets and recovery-key permissions.
- Serializes crash-safe writes per state-file path and fault-injects every replacement boundary, including concurrent writers.
- Adds advanced wizard controls for persistent active/archive log budgets, a read-only archive-prune preview, and an explicit creator-approved prune action that never deletes active logs.
- Canary-updates ESLint to 10.9.1 and typescript-eslint to 8.68.0; TypeScript 7 and Node 26 types remain deferred as separate major migrations.
- Removes the remaining full-browser timing race by showing pending configuration changes immediately and preserving add-on form drafts during background refreshes; all 62 browser cases now pass in one uninterrupted run.
- Expands the public-release canary across the CycloneDX SBOM, release-evidence manifest, add-on index, every optional add-on checksum, and all 15 provenance subjects published with 4.0.8.
- Opens a GitHub issue only after two consecutive scheduled public-attestation failures and closes that issue automatically after recovery.
- Carries the safe numeric active/archive log-storage policy through wizard exports/imports and encrypted move-computer bundles without including credentials.
- Rehearses a transactional portable Node runtime-cache refresh every week, including rollback safety and deliberate corruption rejection.
- Runs TypeScript 7.0.2 and Node 26.4 types as an isolated weekly compatibility canary while production remains on the reviewed TypeScript 6 and Node 22 type lines.
- Applies the same two-consecutive-failure notification threshold and automatic recovery closure to the runtime-cache and next-major toolchain canaries.
- Updates workflow syntax validation to actionlint 1.7.12 and verifies the complete workflow set locally with the checksum-pinned official Windows binary.
- Exercises malformed SBOM, release-evidence, add-on-index, and attestation statements through offline fixtures shared with the public release canary.
- Excludes disposable local caches from typed ESLint discovery, reducing repeated lint overhead without skipping source, tests, scripts, or workflows.
- Pins the actionlint 1.7.12 container to its immutable Docker registry digest rather than relying on a mutable version tag alone.
- Treats cancelled, skipped, neutral, and timed-out automation conclusions as non-failures so they cannot create, update, or close reliability issues incorrectly.
- Requires 4.0.9 release evidence schema v2 to bind the exact clean source commit to the published core archive SHA-256; the public canary remains compatible with already-published 4.0.8 schema v1 evidence.
- Separates source validation from receipt-backed packaging through a commit-, lockfile-, toolchain-, and 24-hour-bound receipt; repackaging still performs a clean import sync and rebuild while safely avoiding duplicate lint, typecheck, test, and configuration gates.
- Shows each daily or weekly canary's latest conclusion, last successful run, age, and freshness directly in Release readiness, and keeps creator review gated until all four canaries are current and successful.
- Reads up to 20 runs from each canary's own workflow endpoint so busy repository history cannot hide a stale or failed release gate.
- Shows the latest five runs, active incident duration, most recent recovery duration, GitHub response cache age, and public API rate-limit capacity in Release readiness.
- Uploads the commit-bound validation receipt as a retained artifact and attests that exact receipt from the protected release environment.
- Records a deterministic unsigned-payload manifest before timestamped Authenticode work, then carries its SHA-256 separately through the final release manifest and installed-build provenance.
- Reuses GitHub responses with persisted ETags, reports conditional cache hits, and pauses refreshes until the documented reset after a public API rate limit.
- Pins every external workflow action to an immutable revision, including compatibility publishing and artifact transfer jobs.
- Rechecks the published runtime signer and trusted timestamp, plus every configured first-party PowerShell signer and timestamp, before post-release smoke can pass.
- Runs TypeScript 7 alone, Node 26 types alone, and both together in isolated migration lanes without changing the production package manifest or lockfile.
- Groups immutable GitHub Action digest refreshes into one weekly Dependabot pull request that still follows protected-main review and validation.
- Replaces the single oversized add-on acceptance with four focused browser scenarios and a deterministic install-completion signal.
- Requires every configured first-party signing certificate thumbprint to match the creator-approved allowlist, blocks certificates with fewer than 30 valid days, and warns within 60 days of expiry.
- Provides a manual draft-PR promotion gate for TypeScript 7 and Node 26 types only after v4.0.9 is published and the three latest scheduled canaries pass.
- Validates all nine downloaded toolchain lane artifacts before promotion, including exact versions, isolation, unchanged manifests, and the complete ordered check set.
- Gives every browser case its own temporary Bridge process, free localhost port, configuration, and add-on data directories so parallel workers cannot share state.
- Adds a protected signing-certificate preflight that applies the release policy without modifying or signing any release file.
- Caches the checksum-verified official actionlint 1.7.12 Windows archive for subsequent offline workflow linting.
- Resolves each documented GitHub Action version tag through the GitHub API and rejects any SHA mismatch before CI can pass.
- Binds all nine promotion artifacts to both the originating workflow head commit and the artifact SHA-256 digest returned by GitHub before extraction.
- Explicitly dispatches protected CI for automation-created promotion pull requests and waits for the exact promotion commit to pass.
- Displays protected certificate-preflight freshness, expiry warning/current state, and remaining days in Release readiness while withholding certificate identity.
- Limits GitHub Actions to the approved first-party `actions` publisher and checks actionlint's upstream GitHub attestation as well as its fixed archive checksum.
- Uses bounded retries and a seven-day matching tag-resolution cache so transient GitHub API outages do not weaken verification or create needless CI failures.
- Publishes GitHub provenance attestations for the exact promotion eligibility and validated canary-artifact reports before creating the draft migration pull request.
- Creates one deduplicated Windows signing-certificate renewal reminder inside the 60-day warning window and closes it automatically after a current protected preflight.
- Retains only sanitized certificate policy and expiry metadata from the protected preflight; certificate subject and thumbprint are not uploaded.
- Temporarily schedules the isolated toolchain soak daily so three qualifying post-release runs accrue in approximately three days rather than three weeks.
- Places the exact GitHub promotion-evidence attestation URL in the generated draft pull request and displays it in Wizard Release Readiness.
- Runs a monthly stale-preflight audit that creates one protected-approval reminder and closes it once current evidence is available.
- Includes GitHub's current artifact-metadata permission anywhere the v4 attestation action publishes artifact provenance.

## Install or update

Run `Install THSV StreamBridge.cmd` from the extracted release. The installer preserves creator configuration, credentials, add-on state, action grants, executable selections, and existing Streamer.bot data while replacing release-owned application files.
