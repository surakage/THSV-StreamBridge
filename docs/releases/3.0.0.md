# THSV StreamBridge 3.0.0

Version 3 is the synchronized bridge and first-party add-on release. It keeps one local Streamer.bot connection and adds centralized add-on coordination, a central reward blueprint catalogue, the reusable Custom Counter add-on, regenerated Version 3 Streamer.bot imports, expanded offline acceptance coverage, and clearer migration and live-test guidance.

## Highlights

- Central coordination supports exclusive, queueable, independent, background, priority, cooldown, cancellation, timeout recovery, cleanup, diagnostics, and a creator-confirmed emergency reset.
- Custom Counter supports up to 20 persistent counters, role-gated commands and actions, optional event deltas, and a customizable lightweight overlay.
- Reward setup now presents stable internal IDs, descriptions, costs, colors, input requirements, cooldowns, limits, settlement behavior, and coordination policy from one source of truth.
- All first-party add-ons, source manifests, browser assets, and generated Streamer.bot imports are synchronized at `3.0.0`.
- The portable installer continues to verify every release file, preserve creator data, retain rollback state, and fail closed when activation is unhealthy.

## Compatibility and migration

The product version is `3.0.0`. The normalized event/add-on contract remains `2.0.0-preview.1` by design. Existing creator configuration and add-on private state are preserved through the installer and schema migration path. Follow the [Version 3 migration guide](../version-3-migration.md) before replacing Streamer.bot imports.

## Platform limits

- Twitch native chat, follows, subscriptions, resubscriptions, gifts, raids, Bits/Cheers, channel reward redemptions, and stream lifecycle use the documented intake matrix.
- Kick native chat, follows, subscription events, gifted Kicks, channel reward redemption, and stream lifecycle use the documented intake matrix. Kick reward creation, editing, enablement, fulfillment, and refunds are not claimed because the current reviewed Streamer.bot interface does not provide parity with Twitch reward administration.
- YouTube and TikTok remain supported through their documented provider paths, with TikTok relying on creator-configured TikFinity mappings.
- Genuine provider acceptance is tracked separately from automated and simulated routing. Financial, reward, raid, moderation, destructive, outbound-chat, Discord, TTS, and scene-changing paths remain pending until their exact live event is observed.

## Verification

The release gate includes typecheck, lint, build, configuration validation, the complete unit/integration suite, Playwright overlay/wizard acceptance, deterministic Streamer.bot import generation, all first-party add-on bundles, portable Windows packaging, archive/checksum verification, a production dependency audit, secret/private-file checks, and final diff review.

Use the [first-live checklist](../live-test-checklist.md) to record genuine Twitch and Kick acceptance. Do not interpret a Streamer.bot test trigger as proof that a provider delivered the same payload in production.

## Distribution

Version 3 is an unsigned portable Windows x64 package. Verify the adjacent SHA-256 checksum and GitHub artifact attestation before installation. Optional add-ons remain separate downloads and are never silently installed or enabled.
