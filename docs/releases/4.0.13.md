# THSV StreamBridge 4.0.13

## Lighter background work

- Keeps one OBS connection open for scene and live-state changes instead of reconnecting every second.
- Caches Streamer.bot and broadcast-app process checks and runs them without blocking the Bridge.
- Writes state files only when something changes, and wakes the monthly add-ons once at the month boundary instead of every minute.
- Countdown and subathon timers still update overlays every second but save state on changes and every 30 seconds. After a crash (not a normal shutdown) a running countdown can restore up to about 30 seconds behind.
- Random Clip Player backs off between retries while Streamer.bot is unreachable.

## Streamer.bot and scenes

- Bridge and wizard launches no longer hold Streamer.bot's WebSocket and Stream Deck ports, so restarting Streamer.bot can't leave them blocked.
- Launch, Shutdown and Open Setup Wizard remember the install folder, so re-importing the launcher package no longer breaks them. Re-importing still removes the action triggers.
- A scene switch reported by both Streamer.bot and OBS is delivered once.

## Raid Scout

- The raid target's clip plays in Twitch's embedded clip player. Twitch only accepts `localhost` for local embeds, so point the Raid Scout OBS browser source at the `localhost` address the wizard shows; a source still on 127.0.0.1 reopens itself on localhost.
- Clip previews can hold a confirmed raid for at most 45 seconds.
- If the stream-online signal was missed, the Ending Soon scene checks live state, or shows an "AUTO-RAID DID NOT RUN" card. Re-import the Raid Scout package for this check.
- Suggest and Confirm and Go Live can no longer be chosen as the Stop Streaming action.
