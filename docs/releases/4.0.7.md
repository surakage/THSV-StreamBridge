# THSV StreamBridge 4.0.7

Version 4.0.7 folds the final live-session findings into one release: exact scene selection, safer restart behavior, complete add-on action checks, durable stream evidence, and quieter recovery when a permanent permission is missing.

## Live-safe reliability

- The authenticated shutdown route and desktop launcher refuse to replace StreamBridge while any platform is live.
- One privacy-safe stream-session journal now survives Bridge restarts, so countdown, go-live, chat, timed-action, ad, clip, raid, and ending evidence remain in the final report.
- Burst session activity is coalesced into one durable journal write every 1.5 seconds, while shutdown still forces the latest state to disk.
- Post-stream reports count capability denials and repeated dispatch failures instead of reporting a clean session when an add-on could not run.
- Repeated capability warnings are consolidated into one incident with a count, first and last occurrence, and recovery time.

## Pre-stream confidence

- Test & finish verifies every fixed broker-dispatched Streamer.bot action used by an enabled add-on is installed, enabled, creator-approved, and intentionally triggerless.
- Broker-dispatched and permanently triggerless actions now carry explicit package contract fields instead of being inferred from queue presentation flags.
- Saved countdown, BRB/random-clip, and Raid Scout ending scenes are checked against fresh, complete enabled OBS, Meld, and Streamlabs catalogues; stale or partial results are rejected.
- Enabled countdown, ad, random-clip, and Raid Scout overlays must have their browser source connected before preflight reports ready.
- Every enabled timed action exposes its last firing, missed-run policy, timezone/DST-safe clock policy, approved target state, and next three projected executions without advancing the timer.
- Raid Scout receives an explicit ending-flow checklist covering the ending scene, search, ad, clip preview, raid attempt, approved output stop, and offline cleanup.
- Meld and Streamlabs scene choices stay hidden until their connection profiles are enabled; existing saved selections remain preserved.

## Wizard and add-on recovery

- Scene settings use a visible detected-scene selector while retaining manual exact-name entry.
- Pending add-on settings and action grants identify affected features and provide one offline-only **Apply changes and verify** action.
- After restart, the wizard performs a mutation-free acceptance check without sending overlays, chat, ads, raids, clips, or broadcast commands.
- Random Clip Player pauses after a permanent grant denial instead of retrying every second; normal transient connection failures remain retryable.
- Changing action grants while live displays an explicit warning and keeps the active runtime unchanged until an offline restart.

## Preserved creator setup

- The version upgrade retains wizard settings, executable selections, protected connection credentials, add-on state, action grants, triggers, and existing Streamer.bot action identities.
- All 42 Streamer.bot import packages are regenerated for 4.0.7 with stable IDs and current trigger guidance.

## Verification

- Lint, type checking, configuration validation, 1,189 passing unit and integration tests, add-on package integrity, and the complete 61-case browser suite gate this candidate.
- Genuine provider events and creator-visible behavior remain live acceptance evidence; the automated acceptance flow does not fabricate on-stream output.

## Install or update

Run `Install THSV StreamBridge.cmd` from the extracted release. The installer preserves creator configuration and state while replacing only release-owned application files.
