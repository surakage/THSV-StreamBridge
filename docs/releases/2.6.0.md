# THSV StreamBridge 2.6.0

This release adds Village Jukebox and hardens the shared reward, points, voice, viewer-card, and clip lifecycles across all first-party add-ons.

## Highlights

- **Village Jukebox** provides YouTube-first song requests from supported chats, bounded fair queueing, optional Viewer Foundation spending, Twitch/Kick reward intake, one shared media slot, and a responsive OBS-compatible player.
- **Reward and point paths** now document and enforce their platform boundary: Twitch and Kick can provide native redemption intake, while YouTube and TikTok use stable-ID Viewer Foundation command spending where supported.
- **Lifecycle reliability** now serializes stateful add-on work, recovers after isolated handler failures, waits for in-flight operations during shutdown, and refunds supported requests that fail before presentation.
- **Random Clip Player** no longer refuses to load when the optional Clip Library Cache helper is absent. It still uses the helper when installed and otherwise uses its approved Streamer.bot lookup action.
- **Wizard guidance** gives beginner steps, required dependency order, exact action approvals, trigger ownership, browser-source checks, and loop-avoidance guidance for every add-on.
- All 33 first-party add-ons and all 36 generated Streamer.bot packages share the `2.6.0` version baseline.

## Install or update

1. Download `THSV-StreamBridge-2.6.0.zip` and `THSV-StreamBridge-2.6.0.zip.sha256` from this release.
2. Verify the checksum using `RELEASE-VERIFICATION.md`.
3. Extract the ZIP and run `Install THSV StreamBridge.cmd`.
4. Open the local wizard and follow the included beginner Bridge Core guide.
5. Download optional add-ons from this same release only. Each add-on ZIP contains its `.thsv-addon`, its own `SETUP.md`, and only its matching Streamer.bot import when one is required.

Normal updates preserve creator configuration, secrets, installed add-on settings/state, uploads, logs, and backups outside the versioned application folder.

## Verification boundary

The repository, browser, package-integrity, and Windows bundle gates are automated. Genuine-provider acceptance remains separate for financial, reward-mutation, moderation, raid, Discord, translation, voice, and media paths. A simulated event proves routing only; it is not recorded as a real-provider pass.
