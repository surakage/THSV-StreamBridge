# THSV StreamBridge 4.0.3

Version 4.0.3 makes release preparation repeatable and keeps live-acceptance reminders focused on the parts of StreamBridge that actually changed.

## Release reliability

- Feature branches run CI through their pull request while direct `main` pushes remain covered; superseded runs are cancelled automatically.
- GitHub Actions workflows are checked with actionlint.
- A reusable, manually dispatchable, and weekly release preflight runs startup chaos plus the same package, clean-install, repair, and upgrade gate used by tag publication without publishing a release.
- Release-candidate tags must exactly match `package.json` and must not already have a published release.
- The previous release ZIP is accepted for upgrade testing only after its published SHA-256 and GitHub provenance attestation verify.
- Install, repair, upgrade, and creator-data preservation results are retained as machine-readable preflight evidence.

## Acceptance reminders

- Provider adapters and core startup, delivery, overlay, and persistence paths use automatic content fingerprints instead of manually bumped contract numbers.
- Unrelated version or build changes no longer expire every live-acceptance check; only relevant component, adapter, configuration, trigger, or add-on changes require another confirmation.
- Existing 4.0.2 numeric adapter bindings migrate to content fingerprints without forcing a one-time blanket recheck.
- Configuration sections and Streamer.bot packages are bound per check, so unrelated creator setting or trigger changes stay accepted.
- Due, due-soon, and changed checks appear on the Wizard Overview and in the Windows tray without exposing evidence notes.
- Tray reminders open directly to the live-acceptance list, support a persistent creator-controlled 24-hour snooze, and repeat no more than once every twelve hours while unchanged.
- The Wizard offers 1-hour, 24-hour, and 7-day reminder choices plus a privacy-safe acceptance change history that omits result notes and viewer data.

## Release operations

- Weekly preflight opens an issue only after two consecutive scheduled failures and closes it automatically after recovery.
- A post-publication smoke workflow downloads every released asset, verifies checksums and GitHub attestations, matches add-ons to their signed index, and performs a clean installation.
- The authenticated Wizard includes a read-only Release Readiness page for lifecycle evidence, public PR checks, and the creator approvals still required before merge, tag, and publication.
- Tagged publication waits at the protected `streambridge-release` GitHub environment; repository settings must require creator review before the release job can continue.
- Post-release failures create one issue per tag, repeated failures update it, and a successful rerun closes it automatically.
- Post-release evidence now covers the latest two stable releases: previous install, current upgrade, current reinstall, creator-data preservation, and downgrade rejection.
- Release Readiness shows the post-release workflow result and links to its retained downloadable evidence.
- The Windows tray offers 1-hour, 24-hour, and 7-day acceptance-reminder snoozes.
- A protected `streambridge-tag` workflow creates an annotated version tag only when the supplied full SHA is still the tip of `main`, matches `package.json`, and belongs to a merged pull request.
- Every release publishes an attested evidence manifest and checksum covering lifecycle/startup proof and every release asset hash.
- Release Readiness persists the last successful public GitHub result under creator-owned state and clearly labels cached results when offline.
- Preflight and post-release issue decisions share one dry-run-capable, unit-tested automation policy.
- Published verification now proves preserve-data uninstall, reinstall, creator/add-on state retention, and recovery-key continuity.

## Install

Run `Install THSV StreamBridge.cmd` from the extracted release. The installer verifies packaged files, preserves creator-owned data, performs a health-checked activation, and rolls back if activation fails.
